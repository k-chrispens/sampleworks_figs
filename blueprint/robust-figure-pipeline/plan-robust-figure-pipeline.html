Expected behavior

One understandable startup workflow

  • Open the landing notebook, select existing output folders, and inspect recognized exports, inferred metadata, failures, coverage, and unresolved identities. Unknown files are reported as unrecognized rather than silently counted as evaluation data.
  • Use a single saved source configuration for roots and necessary metadata declarations. Source discovery must not depend on randomly renamed per-model files or notebook-specific path lists.
  • If sources overlap, show their original filenames, metadata, representative conflicting records, and the affected analyses. Users can distinguish separate runs or model versions, confirm a repeated export of the same evaluation, or explicitly choose a source where appropriate.
  • Renaming a display label alone must not resolve an identity conflict. Preserve original metadata and record the user's identity assignment and rationale. Never infer “same run” merely from equal metric values.
  • Persist resolutions and source fingerprints. Reopening unchanged data does not ask the same questions again; changed sources trigger revalidation and invalidate decisions that no longer apply.
  • Only publish a validated intermediate artifact after structural conflicts are resolved. Before that, show diagnostics rather than figures from partial or ambiguous results. Scientific notebooks opened directly expose a clear “setup required” state.
  • Never modify source folders. Write only to an explicit workspace-owned output location, and keep the last valid artifact intact if a new import fails.
  • Landing owns source choices and import resolutions; science notebooks own their unsaved controls. The saved handoff identifies the artifact version/content and selected recipe/configuration. Each notebook displays what it loaded; rebuilding data does not silently replace an open notebook's frames. Reload is explicit, and export records the actual rendered data/control state. Unsupported artifact/configuration versions produce an actionable error rather than a silent upgrade.

Exploration with explicit scientific choices

  • Select any combination of available models/model versions and an explicit run for each series. Avoid hardcoded Main/Protenix/RF3 groups as the only way to combine models; paper presets can still use those groups.
  • Expose proteins/regions, occupancy splits, baseline and guided conditions, parameter sweeps, aggregation, inclusion rules, metric choices, and supported thresholds. Offer only choices supported by the loaded measurements.
  • Hover exposes condition and region identifiers plus metric values. Point selection exposes contributing source records, not just a shortened label. Aggregated points reveal all contributors and exclusions; selection uses stable identifiers rather than row positions.
  • Each analysis reports its population: available rows, failed evaluations, missing pairs, join exclusions, model coverage, and final contributing regions/proteins. Missing required data produces a clear unavailable state, never a plausible-looking empty plot.
  • Metric functions are ordinary readable Python. UI controls change parameters; computations requiring unavailable upstream measurements are identified as unsupported, not approximated silently.

Reproducible paper outputs

  • A paper recipe records dataset fingerprint, selected run/model identities, selection policy, metric-definition version, parameters, filtering, aggregation, guidance conditions, and highlights.
  • Preparation produces the final plotted coordinates, uncertainty values, stable point identifiers, contributor membership, and exclusions. Interactive and publication renderers only present those values; neither independently chooses populations or performs scientific aggregation. Export SVGs with a small provenance/recipe sidecar; exploratory outputs must not overwrite pinned paper outputs.
  • A tagged release identifies analysis code and paper recipes and references an immutable dataset artifact or release asset with checksums. A code tag alone is insufficient to identify privately changing source folders.
  • Publishing tags, releases, or data is a later explicitly authorized action. Planning and implementation do not automatically publish anything.
  • First reconstruct the generated paper panels from the existing local results/ snapshot and record its file checksums, settings, plotted values, and comparison to the published panel. Work in paper order, starting with Figure 2C's baseline RSCC/clustering distributions. Convert and review each figure interactively before proceeding; do not build the full importer before showing the first reconstruction.
  • A current-code reconstruction is not automatically proof of the historical paper snapshot. Preserve discrepancies for explicit review; incomplete historical metadata can remain visible during exploration without blocking the initial reconstruction.

  • Terms used internally: “model version” was planning shorthand for predictor variant/checkpoint, not a guaranteed CSV field; “run” was planning shorthand for an explicitly associated prediction collection, not a single upstream schema entity; “trial” corresponds to the upstream Trial record and exported trial_dir, usually one protein/occupancy/model/settings output; “evaluation context” was our shorthand for how a measurement was made, such as whole-region versus max-RMSD-window RSCC. Prefer actual source fields and concrete descriptions in the UI.
  • Association rule: the same predicted ensemble can have multiple measurement definitions without becoming a different model. Distinct prediction collections must not be pooled simply because predictor/settings match. User-declared links remain distinguishable from exported evidence; unknown checkpoint/evaluator history is not evidence of equivalence, but may be accepted for labeled exploration.
  • Keep row grain: RSCC/lDDT/minimum-RMSD are trial-selection results; geometry may be trial-member results; classification and training counts are reference-region annotations. Merge these into one container, not a lossy wide join that multiplies or drops rows.
  • Selection semantics: preserve original expressions and explicit scope, chain, region identity, and parent/subsegment relationships where supported. Base-region and max-RMSD-window evaluations remain distinct contexts; containment matching is an explicit analysis rule, not an implicit identity rewrite.
  • Typed values: parse occupancy labels and values, guidance weights, budget parameters, status/error fields, and available classification scores. No exact string-repr occupancy filters or generic “contains chain_id means all altloc” logic.
  • Provenance: retain source file/checksum/record identity, supplied versus exported metadata, evaluation definition/settings when available, contract version, and resolution decisions. Structure paths are references for future viewing, not keys reconstructed throughout the notebooks.
  • Uniqueness: validate per-family keys after identity resolution. Consolidate repeated exports only when the evaluation identity is established; different runs remain different even if their scores match.
  • Missingness: preserve evaluation failures and their errors. Separate legitimate unavailable results from invalid types, conflicting metadata, or failed schema validation. Legacy absence of an error reason remains unknown, not fabricated.
  • Storage approval gate: the user explicitly deferred the container decision. Bring the audited requirements back to the user and obtain approval before implementing artifact persistence; do not silently choose a format while coding. SQLite remains a recommendation only: one file can hold near-source family tables and provenance/resolutions without a server. A single flat CSV/Parquet needs an explicit mixed-grain or sparse representation; a multi-file bundle is another tradeoff against the requested one-file intermediate.

Testing strategy

  • Contract fixtures: include anonymized/small real examples from each retained family, variant collisions, different runs with equal scores, overlapping exports, missing metadata, explicit failures, malformed occupancies, and base/max-RMSD selection contexts. Synthetic examples supplement—not replace—actual writer outputs.
  • Identity and reconciliation tests: preserve run/model/checkpoint/method/budget distinctions; consolidate only established duplicates; retain separate runs when renamed interactively; save/reload decisions; detect changed inputs; reject unresolved conflicting keys.
  • Scientific unit tests: validate baseline pairing without many-to-many amplification, explicit region mapping, mean versus median, minimum-over-members versus aggregation-over-predictors, occupancy denominators including unsupported zero cases, geometry units, threshold boundaries, and failure/coverage counts.
  • Migration integration tests: legacy and new upstream exports for the same evaluation yield equivalent prepared measurements; geometry joins preserve member grain; classifications/training annotations retain their own context; unrecognized files cannot masquerade as supported exports.
  • Import safety: source hashes remain unchanged, including failure paths. Reject output/cache/temp destinations inside the resolved source mount, including paths redirected there by symlinks. A failed new import cannot replace a valid artifact. Reloading an artifact is independent of live source availability; changed folders require explicit rebuild, not silent mutation.
  • Notebook execution: import smoke tests, marimo static checks, and headless execution from fixture artifacts. Exercise direct scientific-notebook startup without setup, missing metric families, and invalid configurations. Keep export side effects in a designated test/scratch location.
  • Browser workflow: choose folders, inspect collisions, distinguish runs, confirm/save resolutions, restart, select arbitrary models/conditions, hover/select points, inspect contributors, and export. Include aggregated points, sorted/filtered frames, empty selections, and unavailable sections.
  • Renderer parity: compare final coordinates, uncertainty values, stable point identities, and contributor membership for interactive/publication outputs, then visually review SVG labels/layout. Test unequal examples where subtracting medians differs from taking the median of differences, so renderers cannot silently choose different aggregation orders. Snapshot numerical tables with appropriate tolerances; do not rely on byte-identical SVGs.
  • Commit coherence and handoff: validate every supported caller when shared loading/analysis changes, rather than retain old APIs for compatibility. Open two scientific notebooks, rebuild the setup artifact, and confirm neither silently switches its loaded data.   • Release reproduction: from a clean checkout, a pinned recipe and checksummed artifact reproduce approved panel tables and SVGs without private directory-name assumptions. Verify all documented exclusions and release references.
  • Performance check: measure discovery/import and typical control changes on a representative full dataset before adding caching or concurrency. Avoid re-reading CSVs for every UI change; optimize further only if measurements justify it.
